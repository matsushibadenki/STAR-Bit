# E030 preregistration: provenance barrier and signature replacement

Date: 2026-09-20, before E030 outcomes.

E029 found three input-rotation-only dual-mux XOR solutions whose final expressions omitted the injected Function but contained early beam signatures compatible with its direct children. Signature equality did not establish origin because another expression can regenerate the same truth table. Test whether Function-derived candidates propagate through later composition, and record when a selected signature changes from a Function-containing representative to a Function-free representative.

Freeze E026's admitted Function and E028's +1 cyclic input rotation. Use fresh seeds 1430–1445, E024's held-out route-selection task `eval_dual_mux_xor`, and numeric control `eval_threshold2`. Compare `no_transfer`, normal `rotate1`, and `one_hop_barrier`: 96 searches, beam 128, six rounds, tree cost at most 16, E026's signature-stable selection, no protected slots. The barrier runs round 1 normally, then forbids any parent expression containing the injected Function from further pairwise composition. Such candidates remain eligible for beam selection and credit, so the barrier removes Function-descendant propagation while retaining their slot and ranking effects. It also permits a later Function-free expression with the same signature to compose. Do not change Functions, tasks, budget, or seeds after seeing outcomes.

For every selected signature and round, save whether its retained expression contains the Function, whether the current parent-pair enumeration offered Function-containing and Function-free generators, whether it was carried from the prior beam, its structural cost, credit, and partner count. Verify in a smoke replay that the unblocked provenance implementation exactly matches E026's outputs and per-round selected signatures.

Primary performance outcome is paired dual-mux exact, `rotate1 - one_hop_barrier`. Support a propagated-descendant mechanism only if the mean gain is at least +0.1875 exact/seed (three net cases), the 20,000-resample bootstrap 95% interval excludes zero, and at least three rotate1-only solutions omit the Function but include a final-expression signature that (a) was first selected as Function-containing with no Function-free generator in that round, (b) was absent from the matched no-transfer beam in that round, and (c) was later selected with a Function-free representative. Report the lineage count even when the performance gate fails; it is observational at the truth-signature level. Secondary comparisons are rotate1 versus no transfer and barrier versus no transfer, exact McNemar tests with Holm correction, mean/unbiased variance, Cohen dz, exact sign-flip p, best error, runtime, solution cost, Function use, and beam overlap by round. Treat the numeric task as a descriptive negative control.

Stop after the fixed 96 searches regardless of outcome. Re-evaluate every exact expression on all 64 inputs. Save raw records, protocol, frozen Function manifest, source hashes, audit and report under E030. This tests Boolean beam-search mechanism, not autonomous concept learning, hardware gate reduction, runtime acceleration, or learned Router behavior.
